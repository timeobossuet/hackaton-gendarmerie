# Checklist de qualité — Cahier des charges UI du dashboard

## Couverture des exigences

- [x] Les exigences utilisent le format `REQ-XXX`.
- [x] Les identifiants sont uniques et séquentiels.
- [x] Les parcours principaux sont priorisés.
- [x] Le périmètre MVP et le hors périmètre sont explicités.

## Testabilité

- [x] Chaque exigence décrit un comportement observable.
- [x] Les états nominaux, vides, de chargement et d’erreur sont couverts.
- [x] Des critères d’acceptation sont fournis.
- [x] Des critères de succès mesurables sont fournis.

## Complétude UI

- [x] La structure de l’écran est décrite.
- [x] Les interactions avec la carte sont décrites.
- [x] Les règles de validation et les messages d’erreur sont cadrés.
- [x] Le responsive et l’accessibilité sont cadrés.
- [x] Les livrables attendus de l’équipe UI sont listés.

## Hypothèses

- [x] Les hypothèses structurantes sont documentées.
- [x] Les fonctionnalités explicitement exclues du MVP sont documentées.
